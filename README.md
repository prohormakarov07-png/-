# Барбершоп «Чёрный дуб»: бот для MAX

Файлы: `max_bot.py` (бот), `storage.py` (запись, цены, отзывы), `config.py` (данные заведения и настройки),
`main.py` и `bot.py` (одинаковые точки входа: запускайте любой), `requirements.txt` (только `maxapi` и `python-dotenv`).

## Запуск на хостинге (панель с Docker/Python)
1. Загрузите все файлы в репозиторий или в панель.
2. Файл запуска: `main.py` (подойдёт и `bot.py`).
3. Переменные окружения (в настройках панели) или файл `.env`:
   - `MAX_BOT_TOKEN`: токен из business.max.ru
   - `MAX_ADMIN_IDS`: ваш ID (сначала оставьте пустым, запустите, напишите боту `/id`, впишите ID, перезапустите)
   - `SHOP_TZ`: `Asia/Yakutsk` (по умолчанию)
4. Запустите и откройте логи. В нормальном запуске будут строки:
   `Запуск бота для MAX. Токен: задан ...` → `Подключено к MAX, бот: ...` → `Бот слушает сообщения (polling)`.
   Когда вы пишете боту, в логе появляется `сообщение от ...`.

## Запуск на своём компьютере
```
pip install maxapi python-dotenv
copy .env.example .env      (Windows)   /   cp .env.example .env   (Linux)
python main.py
```

## Если не работает
- В логе «Токен: НЕ ЗАДАН»: переменная окружения не передана боту.
- «Не удалось получить данные бота»: неверный токен или сервер не достаёт до MAX (проверьте с российского сервера).
- Строки «сообщение от ...» не появляются: бот запущен в двух местах с одним токеном (закройте копию на ПК) или не прошёл модерацию.
- Данные (записи) лежат в файле базы. Если у хостинга контейнер пересоздаётся без постоянного диска, записи пропадут при каждой пересборке.
